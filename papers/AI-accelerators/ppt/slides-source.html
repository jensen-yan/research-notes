ARCHITECTURAL MODEL

两种喂 ALU 的方式。

01 TEMPORAL
硬件猜
硬件藏
CPU/GPU 更典型：cache、乱序、预取、线程调度共同隐藏不可预测延迟。
  • 强在分支多、地址不可预测、低延迟交互
  • 单条或小粒度指令由硬件动态调度
  • 局部性由 cache 透明发现
02 SPATIAL
软件排
数据流
NPU/TPU 更典型：PE 带 local state，数据在 PE 附近停留，并在 PE 之间传播。
  • 强在规则 tensor、可预测 loop 和高复用
  • tile / dataflow 由编译器或 runtime 安排
  • 局部性由软件显式声明

SUMMARY
03 TAKEAWAYS
01

Data movement is the architecture.

算力不是孤立指标，数据路径决定矩阵单元能不能被喂饱。

02

Compiler/runtime is part of the machine.

tile、mapping、DMA、layout、sync 的决策越来越前移到软件栈。

03

XSAI/AME should evolve by evidence.

shared L2 是合理起点；scratchpad、vector、DMA 和更多指令要由 workload 与 gem5 数据推动。
